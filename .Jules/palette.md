## 2024-05-18 - Missing Modal & Custom Keyboard Navigation Bug
**Learning:** Found an accessibility issue where dynamic `img` and `span` tags are used as buttons without `role="button"`, `tabIndex="0"`, or keyboard event listeners for `Enter` or `Space`, making them inaccessible to keyboard users and screen readers. Additionally, found a JavaScript implementation for a Mycology image modal where the corresponding `<div id="myco-modal">` structure was missing from `index.html`.
**Action:** When making custom components interactive (like an image that opens a modal or dots in a carousel), always include `tabIndex=0` to make them focusable, set `role="button"`, and implement `keydown` listeners for standard activation keys (`Enter`, `Space`). Always verify HTML templates include necessary elements that JavaScript assumes are present.
## 2024-05-10 - Explicit focus styles and disabled contexts for custom UI elements
**Learning:** Custom interactive elements like custom carousel arrows, modal close buttons, and custom music toggles do not automatically inherit visually apparent browser-default focus indicators, rendering them functionally invisible to keyboard users. Similarly, disabling elements visually without adding programmatic context (like `title` attributes explaining why it is disabled) fails to guide assistive technology users and can cause confusion.
**Action:** When implementing custom interactive elements, always explicitly define `:focus-visible` states mapping to standard keyboard navigation expectations (e.g., `outline: 2px solid var(--accent);`), and dynamically append explanatory `title` attributes whenever interactive components enter a disabled state.
