## 2024-05-18 - Missing Modal & Custom Keyboard Navigation Bug
**Learning:** Found an accessibility issue where dynamic `img` and `span` tags are used as buttons without `role="button"`, `tabIndex="0"`, or keyboard event listeners for `Enter` or `Space`, making them inaccessible to keyboard users and screen readers. Additionally, found a JavaScript implementation for a Mycology image modal where the corresponding `<div id="myco-modal">` structure was missing from `index.html`.
**Action:** When making custom components interactive (like an image that opens a modal or dots in a carousel), always include `tabIndex=0` to make them focusable, set `role="button"`, and implement `keydown` listeners for standard activation keys (`Enter`, `Space`). Always verify HTML templates include necessary elements that JavaScript assumes are present.
## 2024-05-20 - Custom Interactive Components Accessibility
**Learning:** Found accessibility issues where custom interactive elements like `.myco-dot`, `.myco-arrow`, `.modal-close`, `.music-skip`, and `.music-toggle` were missing focus-visible outlines, making keyboard navigation difficult. Also, visually hidden elements used for screen reader descriptions (`#myco-modal-title`, `#myco-modal-desc`) were improperly hidden with `display:none`, breaking screen reader visibility. Additionally, disabled buttons lacked titles explaining their disabled state.
**Action:** When implementing custom interactive components, always include explicit `:focus-visible` styling (using existing design tokens like `var(--accent)`) to ensure robust keyboard accessibility. Never use `display:none` to hide text for screen readers; instead, use a `.sr-only` utility class that clips the element without removing it from the accessibility tree. Provide a clear `title` attribute for disabled interactive components to communicate their state.
