## 2024-05-18 - Missing Modal & Custom Keyboard Navigation Bug
**Learning:** Found an accessibility issue where dynamic `img` and `span` tags are used as buttons without `role="button"`, `tabIndex="0"`, or keyboard event listeners for `Enter` or `Space`, making them inaccessible to keyboard users and screen readers. Additionally, found a JavaScript implementation for a Mycology image modal where the corresponding `<div id="myco-modal">` structure was missing from `index.html`.
**Action:** When making custom components interactive (like an image that opens a modal or dots in a carousel), always include `tabIndex=0` to make them focusable, set `role="button"`, and implement `keydown` listeners for standard activation keys (`Enter`, `Space`). Always verify HTML templates include necessary elements that JavaScript assumes are present.
## 2024-05-18 - Missing Disabled State Explanations and Missing Keyboard Focus Outlines
**Learning:** Found an accessibility issue where disabled buttons inside the Mycology Carousel custom interactive component lacked a textual description of why they were disabled (e.g., "No previous images"), making it confusing for screen reader users or when hovering. Also discovered that custom interactive elements like `.myco-dot`, `.myco-arrow`, `.modal-close`, `.music-toggle`, and `.music-skip` were entirely missing explicit `:focus-visible` styling, violating accessibility guidelines for keyboard navigation.
**Action:** Always provide contextual descriptions via `title` or `aria-label` when disabling custom controls to prevent confusion. Crucially, when designing custom interactive elements with `role="button"` or `tabindex="0"`, *always* define explicitly recognizable `:focus-visible` states in the CSS to ensure keyboard focus tracking is clear and visually apparent to users navigating without a mouse.
