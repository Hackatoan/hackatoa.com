## 2024-05-18 - Missing Modal & Custom Keyboard Navigation Bug
**Learning:** Found an accessibility issue where dynamic `img` and `span` tags are used as buttons without `role="button"`, `tabIndex="0"`, or keyboard event listeners for `Enter` or `Space`, making them inaccessible to keyboard users and screen readers. Additionally, found a JavaScript implementation for a Mycology image modal where the corresponding `<div id="myco-modal">` structure was missing from `index.html`.
**Action:** When making custom components interactive (like an image that opens a modal or dots in a carousel), always include `tabIndex=0` to make them focusable, set `role="button"`, and implement `keydown` listeners for standard activation keys (`Enter`, `Space`). Always verify HTML templates include necessary elements that JavaScript assumes are present.

## 2024-05-19 - Missing Focus Visible Rings on Custom Interactive Elements
**Learning:** Found a systemic accessibility issue where multiple custom interactive elements (carousel arrows, dots, modal close button, music controls) lacked explicit `:focus-visible` outlines. Relying solely on the browser's default focus ring is often insufficient or overwritten by custom styling, especially on elements with hidden outlines or custom interactions, leaving keyboard users without clear focus indication. Additionally, disabled buttons in custom components (like carousel arrows at boundaries) lacked textual feedback explaining their disabled state.
**Action:** Always verify that custom interactive elements (buttons, custom icons, interactive images) have a clearly defined `:focus-visible` style (e.g., `outline: 2px solid var(--accent); outline-offset: 2px;`) to ensure robust keyboard navigation support. When elements enter a disabled state programmatically, add a `title` attribute or a visually hidden description to communicate *why* they are disabled to all users (including screen reader users).
